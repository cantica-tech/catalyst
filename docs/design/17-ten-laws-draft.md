## 1. Why

Every session pays for the rules. An agent starts from `INVARIANTS.md` (19 KB, 25 entries, about 4.8k tokens) plus the
module's `INVARIANTS.module.md` (5 KB), and is expected to obey 184 KB of rule text in all. Three things make most of
that unnecessary now:

* **R3 turned many invariants into code.** Assent before publishing (INV-4) is an exit code; the home store (INV-6) is
  `catalyst where` and `open`; the journal (INV-17) is written, locked and verified by the CLI; agent switching is
  `catalyst open --agent`. The agent no longer needs the mechanics, only the intent.
* **Several invariants describe mechanisms, not obligations.** INV-20 (template layout), INV-21 and INV-24 (two entity
  types), INV-22 (plugin content) are formats. They belong in the handbook and in `check`, where they already are.
* **Some describe things that are gone or parked.** INV-19 (`/project export|import`, memory notes, agent-owned
  space) predates the home store; INV-10…13 and 22 cover plugins, parked by R4.7.

**Principle.** A *law* is what an agent must judge for itself. Anything a program can decide becomes a `check` rule
(and is enforced, not recited); anything that describes a format goes to the handbook. A law is short enough to be
remembered after context compaction.

## 2. The laws (proposed wording)

| # | Law |
|---|---|
| **L1** | **Record every change, as it happens.** Every change to a governed file is journaled — who, why, which rules it serves, and its content before and after — at the moment it is made, never reconstructed afterwards. Work done outside catalyst is adopted or reverted, never left unrecorded. |
| **L2** | **Ground every change.** Work traces to an artifact, the artifact to a rule, the rule to a domain; a commit names the artifact or rule it serves, or is a `chore:` that changes no rule's behaviour. State the tier (chore, fix, feature) before starting, and escalate it if the work grows. |
| **L3** | **Assent before push.** Nothing leaves the machine — a push, a share, a pull request, a publication — without the user's explicit yes, and no commit lands in a project without it. When a catalyst command exits `3`, it is asking: show the user what it printed and re-run it with `--yes` only once they agree. *(Owner: INV-4 alone.)* |
| **L4** | **Humans decide, agents do the work.** A conflict, a disputed version or a rejected finding is recorded (a `RECON-` case) for a human to settle; the agent never resolves a merge, approves its own work, or signs for someone else. Who signs is declared, never guessed. |
| **L5** | **The criterion lives outside the project.** A project holds `catalyst.toml` and nothing else of catalyst — no paths, no Taskfile, no agent files. The criterion is found with `catalyst where` and made ready with `catalyst open`, the same way by every agent, tool and machine. |
| **L6** | **Never hand-edit what is generated or frozen.** Indexes, backlogs, composed documents and back-references are regenerated by their commands; a deployed definition or a superseded template is changed only by migrating to a new version. |
| **L7** | **IDs are permanent.** Every ID is unique, signed with its creator's `userid`, never reused and never renamed; a retired thing is retired in place, never deleted. At least one user is always active. |
| **L8** | **Install, sync and share only when asked.** Reading catalyst never installs it; a deployment is created, upgraded or shared only on the user's explicit request, with the matching command. |
| **L9** | **The kernel knows no module, and no module knows an agent.** The kernel never names a module's entities; a module never assumes an agent; modules and extensions act on the deployed project, never on catalyst itself. |
| **L10** | **Say what you did and what you checked.** Report outcomes as they are — failed checks, skipped steps, unverified claims; call it "catalyst"; refer to repositories, never to someone's local paths. |

About 2.4 KB, roughly 600 tokens, against 24 KB today. A module may add **at most three** laws of its own (the
software-engineering module needs one, §4).

## 5. What a session would load

`catalyst hook start` and the MCP server's instructions carry the `catalyst open` report, the ten laws and the
module's laws — about 0.7k tokens. Everything else is read on demand: `catalyst why <law|INV-n|rule>` for the
reasoning and the handbook section, `catalyst spec <command>` for a procedure. `INVARIANTS.md` becomes a generated
file: the laws, then the mapping table above.

3. **Park INV-10…13 and INV-22** with the plugins (R4.7), keeping their numbers.
4. **At most three laws per module**, and SE-L1 as the software-engineering one.
5. **Number the laws L1–L10** and keep every `INV-n` resolvable through `catalyst why`, rather than renumbering
   invariants.

instructions to the brief, then start the handbook (R4.2).
