# Results — 2026-10-26: two deployments at kernel 0.117.0, catalyst-ui 0.65.1

After catalyst-users' home moved into catalyst's (`~/.catalyst/users`, kernel 0.111.0), every deployment on an
earlier kernel still read it through the `~/.catalyst-users` link. The owner chose to sync the two deployments this
work had been in, catalyst-users and catalyst-ui, once kernel 0.117.0 was out, and the `standard` landing policy for
both (migration 0.116.0's judgment step).

| What | Where |
|---|---|
| catalyst-users' deployment: 0.110.1 → 0.117.0, landing policy `standard` | `cantica-tech/catalyst-users`, criterion PR #29 |
| catalyst-ui's deployment: 0.106.1 → 0.117.0, Criterion Admin added (migration 0.109.0), landing policy `standard` | `cantica-tech/catalyst-ui`, criterion PR #110 |
| catalyst-ui 0.65.1: the desktop app ships kernel 0.117.0; BUG-000033 | `cantica-tech/catalyst-ui`, `cantica-tech/cantica-tech` |

## The syncs

- Each CLI built from a clean worktree at the 0.117.0 tag; 0.117.0 adds no migration of its own.
- catalyst-ui's roles template gains the kernel's Criterion Admin as `TEMPLATE-ROLES-v4`; migration 0.109.0's
  `catalyst serve` step does not apply (both criteria are shared through git).
- `catalyst landing init --policy standard` in each: an agent session's changes wait for one Criterion Admin's
  approval; a person's own changes, accepted proposals and the server's own merge automatically.
- Both CLIs now read catalyst-users' home in `~/.catalyst/users` directly, and both sign.

## catalyst-ui 0.65.1

- Raising the desktop app to 0.117.0 failed: the payload type generator (`scripts/spec.mjs`) refuses any JSON Schema
  keyword it does not know, and 0.117.0's `serve-landing.schema.json` is a `oneOf`. BUG-000033: a `oneOf` now
  generates the same union as an `anyOf` (TypeScript cannot say "exactly one"), and a union beside `properties` or
  `items` is refused, so nothing is dropped silently. A test pins the generated union.
- `spec/` at 0.117.0 (five new schemas; view, list, change, approve and journal-entry extended) broke no UI code:
  lint, format, typecheck, every package's tests and the Studio bundle pass from a clean build; CI green on #182 and
  #183.
- Another session had released UI 0.65.0 meanwhile; a first bump from 0.64.2 was caught by the version test before
  any commit, and the release is 0.65.1. Its `.vsix` is in the distribution repository, and on the Marketplace (the owner's
  go-ahead; listed about five minutes after publishing).
